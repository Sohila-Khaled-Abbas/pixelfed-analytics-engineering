# Contributing to PixelFed Analytics Engineering

Thank you for your interest in contributing to the **PixelFed Analytics Engineering** project! This repository follows software engineering standards for data pipeline development, schema contracts, and semantic modeling.

---

## Code of Conduct

All contributors and participants are expected to adhere to our [Code of Conduct](CODE_OF_CONDUCT.md).

---

## Development Workflow

### 1. Fork & Clone

```bash
git clone https://github.com/Sohila-Khaled-Abbas/pixelfed-analytics-engineering.git
cd pixelfed-analytics-engineering
```

### 2. Environment Setup

We recommend using Python 3.10+ in a dedicated virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -r requirements-dev.txt
```

### 3. Pre-commit Hooks

Install the pre-commit git hooks:

```bash
pre-commit install
```

## Analytics Engineering Principles

When contributing to this repository, adhere to the following principles:

1. **Schema-First Contract**:
   The 54 tables and 555 columns defined in [`schema.md`](schema.md) (sourced originally from [DrawSQL PixelFed Template](https://drawsql.app/templates/pixelfed)) form the ground truth. Do not modify source column names, column order, or types arbitrarily.
2. **One-Format Ingestion Guarantee**:
   Every table is assigned to exactly one physical format (`csv_gz`, `csv`, `jsonl`, `json`, `xlsx`, `sqlite`). Never create duplicate format copies of the same table.
3. **Reproducibility**:
   Synthetic generation must remain deterministic given the same seed (`--seed 42`) and temporal snapshot (`--as-of 2026-10-14T12:00:00Z`).
4. **Grain-Aware Dimensional Modeling**:
   Avoid collapsing many-to-one or one-to-many relationships into flattened fact tables that induce cartesian fan-out. Respect Kimball's dimensional modeling standards:
   - Conformed dimensions (`dim_users`, `dim_profiles`, `dim_date`, `dim_instances`).
   - Grain-explicit fact tables (`fct_posts`, `fct_likes`, `fct_comments`, `fct_follows`, `fct_media`).
5. **Synthetic Privacy**:
   All data generated by this repository is completely synthetic. Never commit real user data, credentials, private keys, or API tokens.

## Testing & Quality Assurance

Before submitting any Pull Request:

1. Run the automated test suite:
   ```powershell
   pytest -v
   ```
2. Verify code style and formatting:
   ```powershell
   ruff check .
   ruff format --check .
   ```
3. Test small-scale synthetic generation:
   ```powershell
   python src/generate_landing.py --scale 0.02 --seed 999 --output-dir ./tmp_test_landing
   python src/validate_landing.py --landing ./tmp_test_landing
   Remove-Item -Recurse -Force ./tmp_test_landing
   ```

## Commit Guidelines

We enforce the [Conventional Commits](https://www.conventionalcommits.org/) specification:

- `feat:` A new model, ingestion format, or synthetic generator capability
- `fix:` A bug fix in schema parsing, null handling, or relationship generation
- `docs:` Documentation changes, data dictionary updates, or architecture diagrams
- `refactor:` Code refactoring that neither fixes a bug nor adds a feature
- `test:` Adding missing tests or correcting existing tests
- `ci:` Changes to CI/CD workflows or repository tooling
- `chore:` Dependency bumps, maintenance tasks
